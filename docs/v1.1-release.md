# DocTransAI 1.1 正式接入版

本版在v1.0.0转换内核上增加DataProxy ZIP与任务工作区两种完整接入方式。业务项目自行运行DocTransAI与K3，集团DataProxy统一管理源文档与解析资产。详细配置、CLI/Python入口、质量策略和恢复方法见 [接入说明](downstream-integration.md)。

## 交付范围

- `doctransai remote` 上传或复用解析任务、等待并检查质量，通过ZIP或分页文件API取得资料，执行原转换内核。
- 工作区模式回写成品与报告，核对读回内容、使用ETag更新状态、导出ZIP并核对成品哈希。
- 持久化幂等请求ID、job ID、run ID、workspace ID与知识库文档ID；允许单独恢复发布，避免重跑模型。
- 默认拒绝degraded，业务明确允许后才继续；failed、截断模型响应、越界路径和哈希错误不会作为成功输入或输出。
- 新remote入口默认K3 high、每请求16000输出token；原convert入口保留既有默认值。没有增加针对案例名称或业务字段的生产规则。
- 完整源码、依赖锁、配置模板、Dockerfile与接入说明；不包含实际凭证、业务测试样本或运行产物。
- 新增字段审计JSON和HTML。完整记录模板识别位置、原值与最终值、原生证据与操作日志引用；实际填报位置分高确信度、低确信度、未填入三类，标题和标签另列。

### 字段审计追加验收

为两个已完成的成品分别追加了独立上下文K3字段审计，没有重新解析或重跑填写。每份覆盖50个候选位置，识别为23个实际填报位置、27个标题/标签/版式位置。ZIP结果为5项高确信度、6项低确信度、12项未填；工作区结果为6项高确信度、5项低确信度、12项未填。确信度是模型评估，不是统计概率；程序要求完整覆盖、有效引用和直接摘录，不能仅凭写入成功或引用存在判高。

ZIP审计初次把一条有效操作日志ID作为证据引用，旧校验器把所有引用都当源文档ID而拒绝。已用通用规则区分源证据与真实操作记录；操作记录不能单独支持高确信度。保留模型原始assessment，重新校验通过，没有人工补造字段判断。

发现并修复公网gzip弱化ETag的问题：请求identity编码后获取强ETag，正确使用If-Match更新。已经将 `outputs/audit.json`、`outputs/audit.html` 回写工作区，并重新导出和验证全部4个交付文件；原成品内容未变。HTML筛选及低确信度说明已实际预览，程序降级项的操作建议明确要求人工核对，不沿用“直接采信”的旧模型建议。

新remote入口默认完成字段审计后才交付；审计失败会保留保守台账并返回audit_failed。旧convert入口为兼容性先保存pending台账，使用独立audit命令可补齐语义分类。每份审计绑定成品哈希，修改成品后需重新生成对应审计。

### 首轮失败与重试

初次两条链路都使用原5000输出token预算，K3返回 `finish_reason=length`，截断调用未被执行、未发布半成品。显式提高到16000后重新执行成功，沿用原解析任务。表中成功数据属于第二次运行，不是首轮成功率；本次没有人工修改模型产出的DOCX。过程中工具拒绝了无效编辑调用，模型自行修正。
