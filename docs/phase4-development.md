# 第四阶段 独立语义复核与有限修正

## 当前结论

机制已经接入并通过定向边界测试，但语义可靠性验收尚未通过。真实通知单上，同一 kimi-k3 即使用全新上下文、显式事实核对和共同填写要求，仍会把缺乏来源支持的落款日期合理化。因此当前对外只标记 `model_passed`，输出仍命名为 candidate，不将模型判断包装为可靠自动验收。

代码没有加入通知单日期清空规则、台账列名类型转换规则或任何样本映射。修正由模型根据定位明确的复核问题提出，后端只控制范围、版本、格式及执行预算。

## 实现

- 新增 `review.py` 和独立 `document_review_policy.md`，共用已有模型客户端、材料视图、格式后端和有界工具循环。
- `convert` 默认在编辑自检后复核；新增 `review` CLI / `review_document` API，可针对已有输出工作，仍要求提供原模板。
- 复核上下文不包含编辑者的通过结论、编辑历史或上一轮复核的判断。共同填写要求是规则文件，不是模型结论；原模板与当前输出分别提供。
- 复核工具名单只允许读取、查看页面与 `submit_review`，代码层拒绝写入。必须看到当前版本的全部输出页；引用与地址必须可解析。
- 复核按事实支持、完整性、模板保留、图片、版式、数据类型/公式六项报告；`grounding` 记录输出断言、来源断言及各自角色。unsupported/uncertain 不能通过空 issues 隐藏。
- 修正默认最多一轮，仅允许复核定位的范围；版式问题不能借修正改写文字。XLSX 可合并相邻已授权范围，不放开中间未授权单元格。打印区域不得隐藏既有内容。
- 修正前保存检查点；完成后必须再次全新复核。外部文件变化使旧判断失效。所有阶段共享 900 秒，默认每次复核 6 步、修正 4 步；没有无限重试。
- 对外 `model_passed` / `needs_review` / `incomplete` 分开；已有文件均在副本上处理。内部模型 verdict 的 passed 不等于外部可靠验收。

## 实际验证结果

| 场景 | 结果 | 含义 |
| --- | --- | --- |
| 通知单，最初独立复核 | 模型判通过，外部发现漏检 | 换上下文本身不能解决同一模型的推断偏差 |
| 已填台账，最初独立复核 | 模型以沿用模板为由接受文本日期 | 暴露共同填写要求没有充分传入复核的缺口 |
| 正常单条台账对照 | 两种复核版本均未要求修改 | 当前一个正常对照上未观察到无依据修正，不能外推所有样本 |
| 通知单，增加 grounding 与共同要求后 | 仍漏检落款日期 | 模型明确以“源通报当日印发，因此新通知单也可同日出具”合理化，来源没有蕴含该新文书日期；本结果不接受 |
| 已填台账，增加共同要求后 | 找出四个日期字符串并限定修正 | 仅 N3/O3/R3/V3 从文本变为日期值，其他值与图片字节未改变；第二次复核耗尽总预算，正确保留 incomplete |
| 合成跨角色对照 | 发现错误 → 限定修正 → 新复核通过 | 来源只提供净重，候选错误复用到毛重；仅清空无依据的毛重，净重和其他文字保持不变 |

合成对照使用明确标记的 SourceCorpus 测试数据，不是 DataProxy 真实解析运行；用于验证角色核对机制，不能作为真实行业样本通过率。其最终一页已目检。修正后的台账三页已目检，机械核对确认四个日期转换与原值一致，图片字节不变；这不替代已经超时的第二次独立模型复核。

所有早期模型报告保留。通知单漏检和最初台账规则缺口另写 external-verification.json，不重写原始模型输出。早期实验使用的内部 passed/result 文件命名保留在历史目录；最终公开 API 已改为 model_passed/candidate，以明确判断来源。

## 测试与范围

定向测试 101 passed；全库仅收集 475 项，比第三阶段增加 20 项。没有执行全量历史样本，也没有重跑旧链成本对照。

边界测试覆盖：复核无写权限、上下文隔离、缺页与不确定性阻止通过、无效 grounding 不能隐藏、地址/操作范围、相邻范围并集、检查点、修正次数上限、第二次复核失败不能继承成功、文档哈希绑定、外部修改拒绝、有限预算、默认转换接入复核及 CLI 退出码。

## 后续判断

当前不应进入删除旧链或自动交付阶段。仍需解决同模型复核的漏检，以及完整复核/修正在总预算内完成的稳定性。增加个别样本规则或仅扩大超时不能证明可靠性提升；应继续用真实反例与未修改对照衡量漏检和误报。本文只确认独立复核与有限修正机制已实现，不宣布第四阶段质量目标全部达成。
