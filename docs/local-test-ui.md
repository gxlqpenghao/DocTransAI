# 本地测试页面

测试页运行在业务开发者自己的电脑上，复用现有DataProxy接入、模板填写和审计流程。只有源文档提交给DataProxy；目标模板在本地读取和编辑。模型与DataProxy密钥从后端配置读取，不通过页面输入或返回到浏览器。

## 启动

首次配置后双击启动的Windows/Mac操作见[桌面部署指南](desktop-deployment.md)。默认不再需要外部render_docx.py或Codex运行时。

```bash
uv sync --locked
cp .env.example .env
# 在.env中填写实际DataProxy地址、项目Key、LLM配置；安装LibreOffice，渲染器随项目提供
uv run doctransai web --env-file .env
```

在浏览器打开 `http://127.0.0.1:8765`。也可指定端口和任务保存位置：

```bash
uv run doctransai web --env-file /secure/backend.env --port 8765 --runs-dir ./outputs/web
```

仅监听127.0.0.1，不需要额外的Node.js、前端构建工具或Web框架依赖。当前用于单机开发与验收，不提供多用户登录或公网托管。网页顶部展示配置是否齐全；这项检查不调用远端API，不能替代实际连通性验证。修改配置文件后可以点击“重新检查”；修改进程环境变量时需重启服务。

## 操作

1. 选择或拖入一份源文档：PDF、DOC/DOCX、PPT/PPTX、XLSX/XLSM、TXT/Markdown、HTML或常见图片，最大100 MiB。实际解析能力取决于DataProxy配置。
2. 选择目标模板：DOCX或XLSX，最大20 MiB。旧DOC模板请先转为DOCX；PDF不能作为当前填写模板。扩展名和基本Office文件结构都会校验。
3. 上传区下方直接调整模型、输出token预算、思考开关、ZIP/工作区模式，无需打开弹窗。开启与关闭按钮均有悬停和键盘聚焦说明。K3使用后端强度（默认high），关闭置灰；未知模型或尚未适配的服务地址同样禁用开关。
4. 点击“开始转换”，查看解析、资料读取、填写与预览、审计、交付等阶段。当前一次运行一个任务，不会因刷新页面自动重复提交。
5. 下载成品，打开审计弹窗，筛选低确信度和未填写项。在“诊断详情”中也可下载审计JSON、诊断报告、任务记录；工作区方式另提供导出ZIP。

页面不提供转换要求输入框，也不追加隐藏的默认指令。固定填写规则维护在 `src/doctransai/prompts/document_editing_policy.md`，审计规则维护在 `src/doctransai/audit.py`。CLI与Python接口仍支持可选的 `instruction` 供明确的单次业务要求；普通按钮集成直接省略即可。

桌面主界面使用一屏双面板，只展示文件选择、当前状态、审计概览、成品下载和审计入口；设置直接显示在上传区下方；历史任务和诊断详情在弹窗打开。窄屏通过“上传材料 / 运行结果”切换面板。长审计报告和诊断记录在弹窗内滚动，不撑高主页。更换文件会清除当前展示的旧结果，历史文件仍可从“历史任务”打开。

若填写已完成但审计或发布失败，页面会明确标记任务未完整完成；已经生成的文件仍可下载，并标注待复核，不伪装为完整成功。

## 保存与恢复

```text
outputs/web/<本地任务ID>/
├── source/                 # 用户上传的源文件
├── template/               # 用户上传的模板原件
├── request.json            # 文件路径与非敏感设置
├── web-job.json            # 页面状态、阶段与事件
├── worker.log              # 本地排错日志，不通过页面文件接口开放
└── run/                    # 原流程的integration、input、conversion和导出文件
```

页面保留最近30个本地任务入口，实际文件不自动删除。刷新浏览器可继续查看任务；完成后可再次下载。重启本地服务不会自动重跑未完成任务，会将其标记为中断，并保留记录。

按Ctrl+C停止本地服务时，会终止仍由它管理的本地转换进程。已发给DataProxy或模型服务商的远端任务不保证随之取消；可从 `run/integration.json` 找到解析任务ID，按照README的CLI恢复步骤继续使用。页面第一版不提供取消、删除、任意目录浏览或自动重试按钮。

## 验证边界

后端自动化测试覆盖上传校验、文件大小限制、同源请求验证、单任务并发限制、模板与源文件分开保存、下载文件白名单、审计页面隔离、失败信息脱敏和重启状态。转换核心继续使用已有回归测试。

手工/浏览器验收应分别记录界面操作、真实DataProxy解析、模型转换、审计与成品视觉检查，不把模拟后端测试当作真实模型转换。真实验收使用的配置、上传文件、任务ID、日志、截图与成果放在忽略目录中，不提交至公开仓库。

## 思考开关适配

开关同时检查模型ID与后端服务地址，不把省略参数当作关闭。百炼线路的 `qwen3.8-flash`、`kimi-k2.5`、`kimi-k2.6` 使用 `enable_thinking: true/false`；DeepSeek官方线路的 `deepseek-flash`（当前为V4.1 Flash）及官方兼容别名 `deepseek-v4-flash`、`deepseek-v4-flash-vision-exp` 使用 `thinking.type: enabled/disabled`。其他网关需明确适配后才开放按钮。仅更改模型名不会更换后端地址或授权；需自行配置相应服务商的地址和密钥。

Python/CLI可使用 `reasoning_effort='on'/'off'`（CLI为 `--reasoning-effort on/off`），在这些已适配组合上转换为对应请求字段，不会发送字面值on/off作为服务商的reasoning_effort。原有high等强度配置仍然支持。参数协议已通过模拟HTTP测试，完整转换能力仍需单独验收；开发支线的单次审计对照不代表生产模型已切换。

协议依据：[百炼Qwen3.8 Flash](https://help.aliyun.com/zh/model-studio/token-plan-playbook-code-review)、[Kimi](https://help.aliyun.com/zh/model-studio/kimi-api)、[DeepSeek思考模式](https://api-docs.deepseek.com/guides/thinking_mode/)。

## 实时运行动态

运行时右侧展示最近六条真实阶段/工具事件，并显示累计耗时、距上次动态的时间。转换与审计的流式模型请求会报告等待响应、收到思考响应、收到内容、生成操作参数及本轮完成；流式通知最多约每三秒一次，不新增模型调用。不会显示原始reasoning_content、生成正文或工具参数，不将参数生成误标为已执行。没有新事件时只更新等待计时，不虚构完成百分比。观察回调异常不会中断模型请求。

完成、失败或中断后动态区自动收起，记录保留在“诊断详情”。前端每两秒拉取状态；没有提供流式内容的服务商只能显示请求等待和完成事件。旧任务仅能展示原有记录，不能补回当时未记录的实时动态。

## 解析诊断与交付审计的边界

上游degraded是审核提示，页面默认继续使用，取消“允许降级解析”开关。旧页面提交的该设置不再阻断转换。上游警告仅在诊断详情和任务记录中查看；失败解析、缺失交付包及哈希/结构校验失败仍报错。

交付的audit.json/audit.html只包含实际填写字段的三类结果：已填入且确信度高、已填入且确信度低、未填入。固定标题、标签和版式仍在内部核对，但不成为第四类交付结果。字段保留填写前后值、理由、来源证据与关联操作；不附加DataProxy质量总评、原始输入快照、完整运行日志或上游诊断。完整审计工作记录保存在本地audit-diagnostics.json，不通过交付审计下载接口发布。

只有实际影响某字段的来源模糊、缺失或冲突才写入字段理由，不因上游degraded标记直接降低确信度。该变化作用于新生成的审计，历史成品不自动重写。
