# 第二阶段 多格式来源到 DOCX 的通用编辑能力

第二阶段的通用 DOCX 编辑工程能力已完成；真实验收覆盖 4 个不同 case（共 5 次模型运行，包含 1 次失败后的修复重跑）。仍存在明确的业务语义与模板占位内容问题，尚不满足免人工正式交付。

## 范围与实现原则

开发在 `codex/document-tools-refactor` 的独立 worktree 中进行，原工作区未参与修改。DataProxy 仍提供源材料；DOCX 指目标模板与输出格式。DOC、PDF、DOCX、XLSX 来源通过同一材料读取与页面查看路径接入。

根目录 `AGENTS.md` 持久化了用户要求：不按样本名称、case ID、固定答案或业务字段写生产特例。以下操作依据 OOXML 结构与调用参数实现，业务取值交给模型；没有增加槽位识别、字段映射表或针对样本的后处理器。

## 新能力

- `inspect_document`：正文、单元格内部、嵌套表格内部、页眉页脚表格的独立段落地址，以及行地址和合并信息。默认简要结构；指定节点才提供 run 的文字、Unicode 码点范围和直接格式。
- `replace_range`：精确 `[start,end)` 范围与 `expected` 双重校验，处理重复空白；可明确选择现有 run 的格式。优先使用唯一 `replace_text`，避免模型不必要地计算偏移。
- `set_list`：真实 decimal/bullet 编号定义与独立编号实例，支持正文和单元格。保存 numbering.xml，不影响其他列表。
- `repeat_rows`：复制连续行组，横向合并只填一格，纵向合并必须完整选择。返回物理格顺序；支持文字和图片内容、组内分页控制。
- `format_row`：自动、最小或精确行高，以及是否允许行跨页。已有段落格式工具继续控制图文组与页面布局。
- 局部替换保留范围外的书签/批注边界；内部零长度书签原样保留；跨越非零范围边界明确拒绝。整段重写和结构复制不允许破坏书签、批注或节边界。复制时清除重复的段落会话 ID。
- 结构替换后立即注销旧子节点；同批后续操作不能写到脱离文档的旧节点。失败回滚文件、编号和地址。
- `read_source` 返回明确原生页锚点、相关图片及扫描页引用。搜索可分页读取超过 20 条的结果。不猜测本地 Office 重排页码与 DataProxy 页码的对应关系。
- 编辑工具返回变化节点与删除 ID，避免每次重新发送整份文档；全部旧信息仍可显式读取。没有对材料做不可追溯的语义摘要。

## 验证方法

结构测试使用不同语言、重复空白、Unicode 字符、正文/单元格列表、横向/纵向合并、页眉及嵌套表格、受保护书签、回滚后重试等变体，验证行为而不是某份表单的期望答案。

通用结构验证页已用 bundled renderer 渲染并目检：中文、下划线、独立编号及复制后的合并表格正常。真实 XLSX 原文第 1 页也已渲染目检，中文、表格和图片正常。DOC/PDF 源页面在真实模型流程中实际调用。

真实验收仍使用 kimi-k3、12 步和 900 秒预算；没有为个别样本延长预算。下列运行过程中，模型依据工具错误自行更正不计为外部人工修复；程序变更后的重新运行另行列出。

## 必须保留的限制

通知单虽然执行完成且列表/图片布局正常，仍把源检查日期填入新文书落款日期，并直接映射了监督人/负责人角色。模型在 finish 中声称“验收通过”，但未报告这些疑点。这里将其列为外部验收发现，不能以 execution_status=completed 或引用有效证明业务正确。没有加入按该模板清空某个节点的修复规则。

处罚通知单仍保留抬头中的“XX分公司”，模型将其视为固定文字却声称“无残留占位符”；正文条目也采用文本编号，未主动选择真实列表工具。源表未给出明确下午时段，模板原有“下午”仍被保留，属于模板示例信息与源事实的区分问题。这些均记录为未通过的业务/模板清理检查，不写入生产特例修补。

科技表内容较密，6 页包含附件清单，未强行压到固定页数；单位名称栏需要业务确认。独立语义复核、总体耗时/成本收敛仍属后续阶段，未在本阶段伪装实现。

XLSX 输出编辑、浮动文本框、完整嵌套表格替换、跨受保护范围的编辑、进程重启恢复尚不支持。表格行组复制的复杂保护范围会明确失败，不退回旧系统。
